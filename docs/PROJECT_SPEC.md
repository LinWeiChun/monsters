# PROJECT_SPEC.md

# 貘nsters 專案需求規格

## 一、專案概述

貘nsters 是一套以「食夢貘吃掉負面情緒」為概念的情緒記錄與紓壓系統。使用者可以透過文字、錄音、照片、影片與畫心情等方式記錄煩惱或日記，並透過怪獸聊天室、心的軌跡、社群、圖鑑與互動區獲得陪伴感與紓壓體驗。

本版本目標支援：

- Android App
- iOS App
- Web 瀏覽器

目前前端開發優先順序為 Web-first：新 UI 先以 Web 瀏覽器完成與驗收 Responsive Web Design，再確認 Flutter 共用程式於 Android／iOS 可執行。Web-first 僅代表本階段開發與驗收優先目標，不取消三平台支援。

自 Phase 4 起，所有新增或調整 UI 的 Phase 均採 Penpot design-first：先完成或更新 Web／Mobile 畫板與必要狀態，再依 Penpot 實作 Flutter。Web 畫板為第一實作與驗收來源，Mobile 畫板保留作為後續跨平台適配依據；需求或流程異動時，必須先同步 Penpot，再同步 UI 規格與程式。

## 二、核心使用者

1. 有煩惱但無從宣洩，或想記錄生活、煩惱與心情的使用者。
2. 想透過互動區進行紓壓、測驗、遊戲或心理狀態探索的使用者。
3. 喜歡簡單直覺介面、可愛怪獸與蒐集體驗的使用者。

## 三、核心功能模組

### 3.0 陪伴式首頁

- 首頁延續舊版暖黃色、棕色與目前怪獸的陪伴感，但以單一主要行動「記下現在的心情」降低選擇負擔。
- 手機版使用單欄怪獸陪伴區、快捷操作與共用底部導覽；「我的」為個人資料正式入口，右上角只保留通知，密碼鎖與登出由個人資料頁提供。
- Web 桌面版使用 Home／Profile／Annoyance 共用完整導覽與各頁相對版型；中央內容區依頁面重排，不直接放大手機畫面。
- 尚未完成的日記、歷史記錄、社群、圖鑑與互動功能需顯示開發中狀態，不得建立無效導頁或假資料。
- 一般前進與導覽切換不播放頁面位移動畫；只有明確的返回按鈕讓目前頁面由左往右退出，並保留瀏覽器返回堆疊。

### 3.1 會員與登入

- 使用者註冊
- 使用者帳號：註冊時必填且唯一，英文開頭，可包含英文、數字、底線，長度 4 到 50
- 使用者登入
- 登入後若未登出，且距離上次開啟 App 未超過 30 天，Web、Android、iOS 需直接進入主畫面
- 恢復登入時必須使用 refresh token 換發新 Token，不得直接重用可能已過期的 access token；refresh token 採 rolling 30 天 rotation
- 受保護 API 遇到 access token 401 時，前端只允許執行一次共用 refresh request 並重試原 request 一次；refresh token 驗證失敗需清除 session 並回登入頁，暫時性網路錯誤不得誤清使用者 session
- 超過 30 天未開啟 App、使用者登出或本地登入狀態無效時，需重新登入
- Google 登入：Flutter Web / Android / iOS 使用 Google Sign-In SDK 取得 Google ID Token，並交由後端驗證後換發本系統 JWT
- 首次 Google 登入設定個人資料
- 忘記密碼
- 登出

### 3.2 個人資料

- 查詢個人資料
- 修改個人資料
- 生日以 Web／Android／iOS 可用的日曆選擇器輸入，並以 `yyyy-MM-dd` 儲存
- 更改個人頭貼
- 設定或更改四位數密碼鎖
- 忘記密碼鎖
- 個人資料頁提供可見的登出入口；使用者確認後撤銷登入狀態並返回登入頁

### 3.3 煩惱功能

使用者可以新增、查詢、修改與分享煩惱。每筆煩惱使用文字、圖片、錄音或影片其中一種主要記錄方式，並可另外附加一張心情圖；煩惱預設為私人。

新增煩惱流程：

1. 進入怪獸聊天室
2. 選擇煩惱類別
3. 選擇記錄方式
4. 輸入文字或選取一個主要媒體
5. 選擇是否畫心情
6. 記錄煩惱分數
7. 選擇是否分享
8. 顯示建立完成結果

煩惱分數使用 `moodPoint_1.png`～`moodPoint_5.png` 顯示 1 至 5 分的視覺選項；實際送出值仍為整數 1 至 5。

Phase 3 不發放怪獸獎勵；新增煩惱後的隨機怪獸或獎勵於 Phase 6 串接。

### 3.4 日記功能

使用者可以新增、查詢、修改與分享日記。每筆日記使用文字、圖片、錄音或影片其中一種主要記錄方式，並可選擇略過繪圖或另外附加一張心情圖；日記預設為私人。

新增日記流程：

1. 由 `/diaries/new` 進入日記聊天室與引導頁
2. 選擇記錄方式
3. 輸入文字或選取一個主要媒體
4. 選擇畫心情或略過
5. 需要時使用心情畫布
6. 記錄 1 至 5 分的心情分數
7. 選擇是否分享，預設為私人
8. 檢視摘要並送出
9. 顯示日記安全保存完成結果

Phase 4 不發放怪獸或其他獎勵，API 的 `reward` 固定回傳 `null`，完成頁不得顯示假獎勵；日記獎勵於 Phase 6 串接。

Phase 4 UI 以 Penpot `WEB / Diary Flow / Web` 為第一實作與驗收來源，並參考已完成的 `Web / Companion Home` 與 `Annoyance Flow / Web`，對齊共用 Navbar、1200px 內容區、桌面雙欄、字級、間距、色彩、圓角、陰影、按鈕與 Responsive breakpoint。`APP / Diary Flow / Mobile` 保留作為後續 Mobile 適配來源。

### 3.5 歷史記錄

- 查看過去新增的煩惱與日記
- 修改煩惱狀態
- 將未解決煩惱更新為已解決
- 分享或取消分享煩惱
- 分享或取消分享日記

### 3.6 心的軌跡

- 統整煩惱與日記中的情緒分數
- 以圖表呈現心情變化
- 最多顯示最近七次情緒變化

### 3.7 怪獸圖鑑

- 查看所有怪獸
- 查看已獲得怪獸
- 新增煩惱或日記後隨機獲得怪獸（於 Phase 6 串接）
- 更換怪獸造型
- 每日測驗累積獎勵可獲得怪獸造型

### 3.8 社群

- 查看已分享的煩惱與日記
- 對社群文章按愛心
- 對社群文章留言
- 使用匿名或保護隱私方式呈現內容

### 3.9 互動區

互動區包含：

- 解答之書
- 每日測驗
- 深度心理測驗
- 心理小遊戲
- 紓壓方法

### 3.10 使用說明與回饋

- 查看使用說明
- 新增使用回饋
- 分享貘nsters App

## 四、非功能需求

### 4.1 可用性

- 介面需簡單直覺。
- 手機版以單手操作為優先。
- Web 版需在 390px 至 1920px 常用 viewport 維持可讀性與可操作性，瀏覽器視窗縮放時需即時 reflow，不需重新整理。

### 4.2 安全性

- 個人資料需受保護。
- 煩惱與日記預設為私人資料。
- 分享狀態必須由使用者控制。
- 密碼與密碼鎖不得明文保存。

### 4.3 可維護性

- 前後端分離。
- 模組化開發。
- Backend package 使用 layer-first 結構 `com.monsters.<layer>.<module>`。
- API 與資料結構需文件化。
- 不得將商業邏輯混入 UI 或 Controller。

### 4.4 跨平台

- Flutter 專案需支援 Android、iOS、Web。
- 現階段前端採 Web-first 開發與驗收；平台共用功能不得因 Web 優先而移除 Android／iOS 入口。
- Phase 4 與後續 UI Task 必須先完成 Penpot Web／Mobile 畫板；Web 畫板先完成實作與驗收，再以同一份 Flutter 業務與狀態邏輯適配 Mobile。
- 共用 Responsive breakpoint 固定為 Mobile `< 600px`、Tablet `600px - 1199px`、Desktop `>= 1200px`。
- Web 版若有平台限制，需提供替代方案或明確說明。

## 五、舊系統參考原則

`system_data/` 內的舊系統資料僅作為新版需求分析與實作參考。

AI 或開發者可參考舊系統中的：

- 使用者流程
- 功能邏輯
- 畫面操作方式
- 欄位意義
- 怪獸、日記、煩惱、互動區等既有模組設計
- 舊資料表與 API 行為

但不得將舊系統內容直接視為新版需求。

若舊系統與本文件定義不一致，應以本文件為準。  
若發現舊系統存在可改善之處，應整理為新版設計建議，並記錄至 `DECISIONS.md` 或 `TASKS.md`。
