# PROJECT_SPEC.md

# 貘nsters 專案需求規格

> Phase 4.5 的問題、解法、完整 User Stories、實作邊界與驗收方式以 [`PHASE4_5_FOUNDATION_SPEC.md`](PHASE4_5_FOUNDATION_SPEC.md) 為準；註冊、登入與會員管理細節以 [`REGISTRATION_LOGIN_MEMBER_MANAGEMENT_SPEC.md`](REGISTRATION_LOGIN_MEMBER_MANAGEMENT_SPEC.md) 為準；本文件保存產品層需求。

## 一、專案概述

貘nsters 是一套以「食夢貘陪伴使用者整理感受」為概念的非醫療情緒記錄與自我照顧系統。使用者可以透過文字、錄音、照片、影片與畫心情等方式記錄煩惱或日記，並透過貘怪陪伴、情緒足跡、圖鑑、自我探索與受治理的公開暱稱社群獲得整理與陪伴體驗。

本產品不提供診斷、治療、心理健康評分、臨床風險預測或緊急救援服務。私人日記、煩惱、媒體、情緒負荷與自我探索結果不得被 AI、關鍵字或人工後台自動分析。

本版本目標支援：

- Android App
- iOS App
- Web 瀏覽器

第一版正式服務地區限定台灣，最低使用年齡為 13 歲。13 至 17 歲會員需完成監護人同意，只能使用私人核心功能，不得瀏覽、搜尋、發布或互動於暱稱社群。

目前前端開發優先順序為 Web-first：新 UI 先以 Web 瀏覽器完成與驗收 Responsive Web Design，再確認 Flutter 共用程式於 Android／iOS 可執行。Web-first 僅代表本階段開發與驗收優先目標，不取消三平台支援。

自 Phase 4 起，所有新增或調整 UI 的 Phase 均採 Penpot design-first：先完成或更新 Web／Mobile 畫板與必要狀態，再依 Penpot 實作 Flutter。Web 畫板為第一實作與驗收來源，Mobile 畫板保留作為後續跨平台適配依據；需求或流程異動時，必須先同步 Penpot，再同步 UI 規格與程式。

## 二、核心使用者

1. 想以私人方式記錄生活、煩惱與當下感受的台灣使用者。
2. 想透過自我探索、教育內容或一般自我照顧資源整理想法的使用者。
3. 喜歡簡單直覺介面、可愛怪獸與蒐集體驗的使用者。

## 三、核心功能模組

### 3.0 陪伴式首頁

- 首頁延續舊版暖黃色、棕色與目前怪獸的陪伴感，但以單一主要行動「記下現在的心情」降低選擇負擔。
- 手機版使用單欄怪獸陪伴區、快捷操作與共用底部導覽；「我的」為個人資料正式入口，右上角只保留通知，密碼鎖與登出由個人資料頁提供。
- Web 桌面版使用 Home／Profile／Annoyance 共用完整導覽與各頁相對版型；中央內容區依頁面重排，不直接放大手機畫面。
- 尚未完成的日記、歷史記錄、社群、圖鑑與互動功能需顯示開發中狀態，不得建立無效導頁或假資料。
- 一般前進與導覽切換不播放頁面位移動畫；只有明確的返回按鈕讓目前頁面由左往右退出，並保留瀏覽器返回堆疊。

### 3.1 會員與登入

- Email／密碼註冊與 Google 登入
- 不提供使用者自訂 `account`；Email／密碼帳號以已驗證 Email 登入，Google 帳號以已連結 Google `sub` 登入
- Email／密碼註冊後進入 `PENDING_EMAIL_VERIFICATION`，完成 Email 驗證前不得建立私人內容
- 初始註冊只收 Email、密碼與目前 Terms／Privacy 接受版本；新會員與既有 Email 的公開結果一致為已受理
- Email 驗證連結有效 24 小時且單次使用；重寄有 60 秒冷卻、Email／IP 多維度限流與可靠寄送重試
- 七日仍未驗證且沒有任何私人、社群或個人化資料的空會員可由排程安全清除
- 完成 Email 驗證後進入生日、服務地區與年齡資格流程
- 13 至 17 歲的 Guardian Consent 為 `PENDING_ELIGIBILITY` 內的資格子流程，以 `nextAction` 表達；監護人以一次性 Email 連結同意特定版本條款，但不能查看會員內容
- Google Email 必須為已驗證；Google Email 與既有會員相同時不得自動合併或核發一般Session，需先以既有Email／密碼登入、取得五分鐘`LOGIN_METHOD_LINK`用途reauth，再以新Google ID Token明確確認連結；成功保留目前Session並撤銷其他Session
- 一般會員 Access Token 有效 10 分鐘；工作階段閒置 30 天或最長 90 天後需完整登入
- Refresh Token 為可輪替的不透明 Token；Web 存於 HttpOnly Cookie，Android／iOS 存於 Keychain／Keystore
- 每次完整登入建立獨立Session Family；Backend只保存Refresh Credential hash，10秒內合理並行回相同輪替結果，逾期reuse只撤銷該family
- 受保護 API 遇到 access token 401 時，前端只允許執行一次共用 refresh request 並重試原 request 一次；refresh token 驗證失敗需清除 session 並回登入頁，暫時性網路錯誤不得誤清使用者 session
- 提供分頁裝置工作階段清單、撤銷單一裝置、只登出目前裝置、登出其他裝置與全部登出；其他／全部撤銷需五分鐘、用途限定的密碼 reauth
- 裝置資訊只保存平台類型與白名單化的約略摘要，不保存 IP、完整 User-Agent、硬體識別碼或持久裝置指紋
- 忘記密碼對所有Email統一受理，使用15分鐘、一次性、只保存雜湊的Email重設連結；正式API不回傳Token，成功後撤銷全部工作階段並要求重新登入
- 修改密碼、Email、登入方式、匯出、刪除或重設本機隱私鎖前，需於五分鐘內完成用途受限的重新驗證
- 密碼採 15 至 128 個 Unicode 字元、弱密碼封鎖、無固定字元組成規則；新雜湊使用 Argon2id，既有 BCrypt 於成功登入時漸進遷移
- 登出、密碼／角色／資格變更或 Token 重播時立即撤銷相關工作階段

### 3.2 個人資料

- 查詢個人資料
- 修改個人資料
- 生日在資格確認前可修正；完成資格流程後不得於一般個人資料頁自由修改
- 生日更正需重新驗證、提出理由並由人工稽核，任何年齡降低必須立即重新套用兒少限制
- 個人頭貼只能從本人已取得的貘怪圖鑑素材中選擇，不接受使用者上傳圖片
- Android／iOS 可設定每台裝置獨立的四位數本機隱私鎖；PIN 不同步至後端
- App 進入背景立即遮蔽，預設離開一分鐘後需解鎖，可選立即、1、5、15 分鐘，但不能永久停用
- 忘記本機 PIN 需先完成帳號重新驗證，再重設該裝置隱私鎖
- Web 不使用四位數 PIN，閒置 15 分鐘後要求帳號重新驗證
- 個人資料頁提供可見的登出入口；使用者確認後撤銷登入狀態並返回登入頁

### 3.3 煩惱功能

使用者可以新增、查詢、修改煩惱，並以獨立公開快照分享。每筆煩惱使用文字、圖片、錄音或影片其中一種主要記錄方式，並可另外附加一張心情圖；煩惱永遠以私人 Entry 為來源。

新增煩惱流程使用伺服器端持久草稿。每位登入使用者最多保留一份煩惱草稿，文字、目前步驟、類別、記錄方式、分數、分享選擇與暫存媒體需自動保存；離開頁面、重新整理、重新開啟 App 或更換裝置後，重新進入新增煩惱時需恢復同一份草稿。草稿預設私人，保留 30 天；完成建立或明確放棄後刪除。

新增煩惱流程：

1. 進入怪獸聊天室
2. 選擇煩惱類別或略過
3. 選擇記錄方式
4. 輸入文字或選取一個主要媒體
5. 選擇是否畫心情
6. 記錄情緒負荷或略過
7. 選擇是否建立暱稱社群公開快照
8. 顯示建立完成結果

情緒負荷使用 1 至 5 分，1 代表較輕、5 代表較重，實際送出值為整數。UI 必須同時提供文字語意與「這次不評分」，不得把分數稱為快樂程度、心理健康或疾病嚴重度。

Phase 3 不發放怪獸獎勵；後續只依透明、固定且不重複的解鎖里程碑發放，不使用隨機抽取。

### 3.4 日記功能

使用者可以新增、查詢、修改與分享日記。每筆日記使用文字、圖片、錄音或影片其中一種主要記錄方式，並可選擇略過繪圖或另外附加一張心情圖；日記預設為私人。

新增日記流程使用伺服器端持久草稿。每位登入使用者最多保留一份日記草稿，文字、目前步驟、記錄方式、分數、分享選擇與暫存媒體需自動保存；離開頁面、重新整理、重新開啟 App 或更換裝置後，重新進入新增日記時需恢復同一份草稿。草稿預設私人，保留 30 天；完成建立或明確放棄後刪除。

新增日記流程：

1. 由 `/diaries/new` 進入日記聊天室與引導頁
2. 選擇記錄方式
3. 輸入文字或選取一個主要媒體
4. 選擇畫心情或略過
5. 需要時使用心情畫布
6. 記錄 1 至 5 分的心情分數
7. 選擇是否分享，預設為私人
8. 檢視摘要並送出
9. 顯示日記安全保存完成結果

Phase 4 不發放怪獸或其他獎勵，API 的 `reward` 固定回傳 `null`，完成頁不得顯示假獎勵；日記獎勵於 Phase 6 串接。

Phase 4 UI 以 Penpot `WEB / Diary Flow / Web` 為第一實作與驗收來源，並參考已完成的 `Web / Companion Home` 與 `Annoyance Flow / Web`，對齊共用 Navbar、1200px 內容區、桌面雙欄、字級、間距、色彩、圓角、陰影、按鈕與 Responsive breakpoint。`APP / Diary Flow / Mobile` 保留作為後續 Mobile 適配來源。

### 3.5 歷史記錄

- 查看過去新增的煩惱與日記
- 依日期、類型、私人分類、有無媒體與本人輸入的關鍵字篩選
- 修改煩惱狀態
- 將未解決煩惱更新為已解決
- 建立、更新或取消 Diary／Annoyance 的公開快照
- 搜尋只服務當次本人查詢，不保存搜尋興趣、不建立向量或 AI 分析

### 3.6 心的軌跡

- 統整 Diary 與 Annoyance 中由會員自願填寫的情緒負荷
- 以最近 30 個日曆日的每日趨勢呈現；同日多筆取平均，無資料日期留白
- 依 Entry 建立當下的本地日期分組，後續更換時區不得移動歷史日期
- 可合併顯示或依 Diary／Annoyance 篩選，並能查看當日原始分數
- 不進行診斷、風險預測、自動警示或缺值推測

### 3.7 怪獸圖鑑

- 查看所有怪獸
- 查看已獲得怪獸
- 完成新手流程後，從核准的起始貘怪中自行選擇一隻
- 依公開、固定且不重複的解鎖里程碑取得貘怪或造型
- 里程碑只計算完成自我照顧或教育行動，不讀取文字、媒體、分類或情緒負荷
- 不設隨機抽取、重複補償、連續登入、排行榜、虛擬貨幣或付費解鎖
- 更換怪獸造型
- 使用者可從已取得圖鑑項目中選擇私人個人頭貼
- 累積完成教育小測驗可構成里程碑，但不要求連續日期、不因答錯扣除進度

### 3.8 公開暱稱社群

- 社群只對已登入、完成成人條款且未受社群限制的 18 歲以上會員開放
- Community Post 是由會員逐項確認文字、媒體與公開主題後建立的獨立快照；私人原文修改不得自動更新公開內容
- 情緒負荷、原始建立日期、私人分類、修改歷史與自我探索結果不得自動公開
- 對外顯示會員已確認公開的非唯一暱稱；平台內部保存 owner 關聯以處理治理，但不得公開 Email、會員 UUID、生日、私人 Profile 或私人頭貼
- 公開暱稱可跨貼文辨識，不能用於登入或 owner 判斷；首次發布前需明確確認，並禁止官方身分冒充名稱
- 只提供單層留言與一種非競爭式支持；不提供私訊、追蹤、好友、標記、公開支持數或排行榜
- 未登入者、未成年會員、搜尋引擎與第三方爬蟲不得瀏覽、索引或取得永久媒體連結
- 一般排序以時間與安全條件為主，不以支持或留言量建立熱門排行
- 提供檢舉、封鎖、作者取消分享／刪除、人工下架、社群限制、申訴與不可修改的稽核
- 封鎖後，執行封鎖者不再看到被封鎖會員的 Community Post／Comment；UI 可顯示處置前已公開的暱稱，但不得揭露 account、Email、會員 UUID 或私人 Profile
- 作者取消分享或刪除後，貼文、留言與支持立即不可見並於七天內清除；重新分享建立全新討論
- 作者或審核員可加上非診斷式敏感內容警示；圖片／影片預設遮蔽，音訊不自動播放
- 社群不做預先審核、AI 審核、關鍵字自動處分、檢舉數自動下架或自動通報
- 「自傷／傷人疑慮」檢舉進入人工優先佇列，但檢舉不是緊急救援或 24 小時監控服務
- 檢舉、封鎖、人工審核、停權、申訴、稽核及特權角色 MFA 未完成前，社群功能開關必須保持關閉

### 3.9 互動區

互動區將內容分為：

- 自我探索：沒有對錯、只提供描述性回饋，結果完全私人且可逐筆刪除
- 教育小測驗：具有可驗證答案、說明、來源與適用年齡，不建立能力排名
- 外部資源：經允許清單與內容審閱後，由會員主動離站開啟
- 解答之書與心理小遊戲若保留，必須明確歸入上述類型或另行完成 DoR，不得宣稱診斷或治療

所有正式內容須保存來源、版本、適用年齡、審閱者與更新日期。Admin 可建立草稿，但只有獨立 `CONTENT_REVIEWER` 能核准特定版本；草稿修改後必須重新審閱。

### 3.10 使用說明與回饋

- 查看使用說明
- 新增使用回饋；回饋與社群檢舉分離，第一版不接受附件、日記或媒體
- 回饋案件關閉 90 天後清除文字，只保留不含個資的彙總
- 第一版不提供把社群內容或私人資料轉貼到外部平台的功能

## 四、非功能需求

### 4.1 可用性

- 介面需簡單直覺。
- 手機版以單手操作為優先。
- Web 版需在 390px 至 1920px 常用 viewport 維持可讀性與可操作性，瀏覽器視窗縮放時需即時 reflow，不需重新整理。

### 4.2 安全性

- 個人資料需受保護。
- 煩惱與日記預設為私人資料。
- 煩惱與日記草稿只能由擁有者讀取，草稿媒體不得因分享選擇而對其他使用者開放。
- 公開快照必須由使用者逐項確認，私人修改不得自動公開；分享與取消分享只能由使用者控制。
- 密碼與本機隱私鎖 PIN 不得明文保存。
- 第一版不採端對端加密；使用 HTTPS、私人 R2、Database／R2／備份靜態加密、最小權限與稽核。
- 管理員、審核員、內容審閱者與客服不得查看私人 Entry、自我探索結果或原始媒體。
- App 不得將 JWT、Refresh Token、完整登入結果或私人內容寫入 SharedPreferences。
- 第一版不持久化離線私人資料；尚未同步的本機草稿只在目前執行期間保留，已同步的 owner-scoped 伺服器草稿依本文件的 30 天規則保存。
- 正式環境禁止廣告 SDK、跨站追蹤、裝置廣告識別碼及敏感使用行為分群。

### 4.2.1 資料權利與保存

- Terms、Privacy Policy、Community Rules、Minor Notice 與 Guardian Consent 分別版本化；重大變更要求重新同意，拒絕時仍可匯出或刪除。
- 個別內容刪除後立即不可見，MySQL 內容與媒體 metadata、R2 object 於七天內清除。
- 帳號刪除需重新驗證，立即停用並提供七天取消期；到期後清除身分、憑證、內容、媒體與社群資料。
- 加密備份與 R2 舊版本最長 30 天輪替，還原後必須重播刪除、取消分享與撤銷事件。
- 使用者可經重新驗證匯出個人資料、Entry、情緒負荷、Self Exploration、圖鑑、自己的 Community Post／Comment 與原始媒體；不得包含其他會員內容或內部稽核。
- 一般 Log 保存 30 天、安全事件 180 天、管理／審核事件一年；不得保存私人原文、Token 或可回推已刪除會員的資料。
- 連續三年沒有成功登入的帳號，於 90、30、7 天通知後進入帳號刪除程序。
- 只有正式且具拘束力的法律要求可形成最小、隔離、限期且定期複核的法律保全。

### 4.2.2 媒體與容量

- 既有單檔限制維持：圖片／心情圖 5 MB、錄音 10 MB／5 分鐘、影片 50 MB／60 秒。
- 媒體先進隔離區，完成真實格式解析、重新處理、中繼資料移除與惡意檔案掃描後才可使用。
- 每個會員正式媒體總量第一版為 1 GB；達上限只停止新增媒體，不自動刪除或壓縮既有資料。
- Diary／Annoyance 私人文字上限 20,000 字、Community Post 10,000 字、留言 1,000 字。

### 4.3 可維護性

- 前後端分離。
- 模組化開發。
- Backend package 使用 layer-first 結構 `com.monsters.<layer>.<module>`。
- API 與資料結構需文件化。
- 不得將商業邏輯混入 UI 或 Controller。

### 4.4 跨平台

- Flutter 專案需支援 Android、iOS、Web。
- 現階段前端採 Web-first 開發與驗收；平台共用功能不得因 Web 優先而移除 Android／iOS 入口。
- Phase 4 與後續 UI Task 必須先完成 Penpot Web／Mobile 畫板；Web 畫板先完成實作與驗收，再以同一份 Flutter 業務與狀態邏輯適配 Mobile。
- 共用 Responsive breakpoint 固定為 Mobile `< 600px`、Tablet `600px - 1199px`、Desktop `>= 1200px`。
- Web 版若有平台限制，需提供替代方案或明確說明。
- 某平台對真實使用者開放前，必須通過該平台完整端對端與真實裝置驗證；刪除、匯出與安全功能不得以「開發中」代替。

### 4.5 可用性與無障礙

- 第一版正式語言為台灣繁體中文，但文案、日期、數字與錯誤訊息必須可國際化。
- 核心流程依 WCAG 2.2 AA 設計，支援鍵盤、焦點、螢幕閱讀器、系統大字與減少動態效果。
- 情緒負荷需同時提供數字與文字語意，不得只靠顏色或圖片表達。
- 通知採最少揭露；鎖定畫面不得顯示日記、貼文、留言、媒體或情緒負荷。

### 4.6 商業與內容使用

- 第一版完全免費，不含訂閱、內購、付費容量、代幣或付費貘怪。
- 使用者內容只授權提供儲存、同步、顯示、備份、安全處理及使用者主動分享所需用途。
- 內容不得用於生成式 AI、情緒模型、廣告模型、宣傳或研究；未來新增用途須另行取得明確且特定的同意。

## 五、舊系統參考原則

`system_data/` 內的舊系統資料僅作為新版需求分析與實作參考。

AI 或開發者可參考舊系統中的：

- 使用者流程
- 功能邏輯
- 畫面操作方式
- 欄位意義
- 怪獸、日記、煩惱、互動區等既有模組設計
- 舊資料表與 API 行為

但不得將舊系統內容直接視為新版需求。

若舊系統與本文件定義不一致，應以本文件為準。  
若發現舊系統存在可改善之處，應整理為新版設計建議，並記錄至 `DECISIONS.md` 或 `TASKS.md`。

## 六、開發優先順序

1. 專案基礎架構
2. 會員登入與個人資料
3. 煩惱功能
4. 日記功能候選成果整合

7. 怪獸圖鑑與固定解鎖
8. 自我探索、教育小測驗與外部資源
9. 私人核心封閉測試
10. 公開暱稱社群治理與功能
11. 使用說明與回饋
12. 正式發布驗證

`feature/phase4` 尚未正式整合至 `develop`。完成 Phase 4 整合後，必須先完成第 5 項基礎階段，才能開始原 Phase 5 以後的功能；本規格更新本身不執行 Phase 4 整合。
